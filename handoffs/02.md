# Handoff 02: Turn asymmetry

## Built
In `updateSharkBody`, when the amplitude is nonzero, `applyWave` now adds the turn asymmetry to the body wave. Each node's offset along the spine's left normal is

A·L·amp(s)·(sin θ + a_left·(2/π − 4/(3π)·cos 2θ)), θ = k·s − phase,

with one body-wide a_left from `asymmetryTowardLeft(bodyTurn(...))`. a_left = −a_max·clamp(body turn / full curvature, −1, 1), so it is positive when the outside of the turn is screen-left (a turn to the right). Frequency, phase, front stiffness, the length pass and the body line are unchanged. At zero amplitude the early return still skips the wave, so there is no asymmetry.

`bodyTurn` is the nose path's heading change over the last L, divided by L. Each path point gets the heading of the segment that leaves it, and the newest point gets `kin.heading`. Within a segment the heading is interpolated linearly. The unwrapped change is summed segment by segment, because the body can span more than π (4.8 rad at 1.6 /m). This is exact for paths made by `integrate` or `turnStep`, which move along the old heading and then turn. The tail at `nose − L` always lies in a segment with both end headings known. So nothing is extrapolated, and the heading stays continuous when the tail passes a path point or the trim drops one.

Measured (test tolerance probing):
- R6 and R11 offsets are within 0.3 mm of the spec formula (tolerance 1 mm).
- R12 worst excess: 0.72 mm on the half turns, 1.06 mm and 1.57 mm on the S-turn (tolerance 2 mm). The 1.57 mm is built into the design: the scripted S-turn flips the yaw rate from −0.8 to +0.8 in one frame, so the body turn's slope flips. The kink is d²(body turn) = 1.6/L · v·dt per frame.

## Interfaces provided
- `BodyParams::asymmetry_max` (0.5, dimensionless) and `BodyParams::asymmetry_full_curvature` (0.8, 1/m). Set in `fishes.cpp` (`SHARK_BODY`) and `tests/test_support.h` (`bodyParams`).
- In `shark_body.cpp`, anonymous namespace:
  - `float bodyTurn(const std::vector<PathPoint> &path, Vector2 nose_heading, float length)`: 1/m, signed like `kin.r`. ⚠ Takes `kin.heading` as well as the path; see Deviations.
  - `float asymmetryTowardLeft(float body_turn, const BodyParams &params)`.
  - `applyWave(spine, phase, asymmetry_toward_left, params)`: gained the asymmetry argument.
- Issue 01's per-node `pathCurvatureAtNodes` is not used, as planned.
- New test file `tests/turn_asymmetry_tests.cpp` (R6, R7, R11, R12), added to `shark_body_tests` in `CMakeLists.txt`.

## Deviations
- ⚠ The body turn reads `kin.heading` for the heading at the nose, not only the nose path. The spec says "it reads the existing nose path". Reason: my first version used only the path. It put the window's tail end up to one segment behind `path[0]`, so the heading there was extrapolated, and R12 failed on the cruise S-turn (2.19 mm), with a step when the tail passed the inflection. Keeping more path behind the tail would also fix it, but the existing trim tests require `nose.arc − path[1].arc < L`. `kin.heading` is exactly the direction of the next path segment, and it is not new state.
- R12 S-turn: the spec gives no padding for it. I used the half-turn layout: 1 L straight, 90° one way, 90° the other, 2 L straight.
- R8: the existing test's title now says "(1 + a_max) 0.3 rad". Its allowance is `(1 + params.asymmetry_max) · 0.3`. It also passed at 0.3 rad.
- R6 and R11 use 6 nodes, so every node sits on an envelope knot (as in the existing "six amplitude points" test). Their nose paths come from exact track geometry (`Track`), not from `turnStep`.
- Test order: R7 passed on its first run, because the body turn on a straight path is 0. R11 was written after the code, which R6 drove. I confirmed that each can fail with a mutation: a bias of 0.05 /m fails R7 (5.9 %), and a body turn averaged over L/2 fails R11 while R6 still passes.

## Not verified
- The look in the running app. The user judges it by eye.
- R12 at frame rates other than 60 fps, and with uneven dt.
- The cost of `bodyTurn`: one `atan2` per path point per shark per frame (about 180–400). Not measured.
- With `integrate` in the app the yaw rate changes through the T_r lag, so the kinks should be softer than in the scripted R12 swims. Not measured.
