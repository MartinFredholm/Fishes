# Handoff 05: Pivot path and head arc

## Built
- For the shark, `kin.pos` is the pivot at s_p = `BodyParams::pivot`. `SHARK_BODY` in `main` sets it to 1/3.
- `SharkBody::pivot_path` records the pivot's track. Layout: oldest point first, `kin.pos` last.
  - Each update appends `kin.pos` unless it equals the last point exactly. So v = 0 with `kin.pos` unchanged adds no track.
  - `trimPath` then drops the oldest points it does not need. It keeps the shortest suffix that covers (1 − s_p)·L.
  - An empty path is treated as spawn. A default-constructed `SharkBody` therefore updates like a seed. 04's R6 test relies on this.
- Placement (`placeSpine`):
  - Nodes with s_i ≥ s_p are interpolated on the path polyline at (s_i − s_p)·L behind `kin.pos`. If float rounding leaves the path slightly short, the oldest segment is extended.
  - Nodes with s_i < s_p go on the head arc at (s_p − s_i)·L ahead. This is 04's closed-form arc, run forward. κ = r/v, and κ = 0 when v ≤ 0. If κ is infinite (denormal v), the head nodes sit at `kin.pos`.
- `seedSharkBody` lays a two-point straight path, (1 − s_p)·L long, behind `kin.pos`. It then builds an ordinary frame at phase 0 with the wave on.
- 03's wave, phase and length pass are unchanged. `wave_amplitude == 0` still skips all three.
- `updateSharkBody` reads only the previous `phase` and `pivot_path`, never the previous spine (R22).
- New tests are in `tests/pivot_path_tests.cpp`: R6, R7, R11 at s_p, R12 (R7 at A = 0; R9 and R10 with the wave on), R20 (three tests), R21 and R22. The test's `Swimmer` integrates the track in double precision, with 64 substeps per frame. The test computes the head arc by numerical integration.
- The retired tests are deleted, together with their helpers. The R8 test is adapted. The review 03 nose-sway test is marked `doctest::skip()` with the description "moves to issue 06".

## Interfaces provided
As planned:
```cpp
struct BodyParams { /* …existing… */ float pivot; };   // s_p, fraction of L
struct SharkBody {
    float phase = 0.0f;
    std::vector<Vector2> pivot_path;  // world m, oldest first, kin.pos last
    std::vector<Vector2> spine;
};
```
`seedSharkBody` and `updateSharkBody` keep their signatures.

## Deviations
- R8 test: besides the expected along-position, I added `params.pivot = 1.0f / 3.0f;`. Fields left out of a designated initialiser default to 0. Without this line, (s − s_p)·L would equal s·L, and the adaptation would test nothing.
- Kept tests from 01–04 do not set `pivot`, so they run with s_p = 0: nose at `kin.pos`, whole body on the path. They still pass. To cover the real configuration, `pivot_path_tests.cpp` repeats R6, R11 and R12 (R9, R10) and the R20 finite-coordinate check at s_p = 1/3.

## Not verified
- Visual: the user still needs to watch the shark start a turn in motion. Four stills from a 10 s run show two red polylines, about 150 px long, smoothly curved. Stills cannot show whether the head swings in at once or whether the body slides sideways.
- R7, R12, R20 and R22 passed on their first run, because the R6 code already placed every node. Mutation checks: flipping the head arc's turn side fails R7, and disabling the trim fails R21. R22 cannot fail by construction, since the update never reads the old spine.
- R20's "nodes behind the pivot stay put at v = 0" is tested only at A = 0. With the wave on, a head change at v = 0 (curved → straight) moves the tail through the head-to-tail length pass. I did not measure how far.
- Path size is unbounded for vanishingly small steps: one point per frame, so need / (v·dt) points. In the app, v ≥ v_min keeps it at about 240 points at 60 fps.
