# Handoff 01: Tracer — spine follows the nose path, drawn as a polyline

## Built
- `kinematics.h`: `Kinematics`, moved out of `fishes.cpp` unchanged.
- `shark_body.h` / `shark_body.cpp`: seeding and the body update seam. The update appends the nose (`kin.pos`) to the path, trims it, and places the spine nodes on it by arc length. No body wave: `phase` is never changed and `dt` is unused (`[[maybe_unused]]`, for issue 03).
- `tests/shark_body_tests.cpp`: doctest tests for R5, R6, R7 (straight and circle), R12 (uneven dt on a circle at 1.0 and 2.5 m/s).
- `third_party/doctest/doctest.h`: doctest v2.4.11 (version confirmed by the user).
- CMake: static library `shark_body` (raylib headers only, no raylib link), test executable `shark_body_tests` registered with CTest. `fishes` links `shark_body`.
- `main`: each `Shark` has a `SharkBody body`, seeded at spawn, updated after `integrate` from `sharks_old[i].body` into `sharks_new[i].body` (double-buffered). Sharks are drawn with `drawSpine` (`DrawLineStrip` through `spine`, converted with `toPixels`). Fish untouched.

Build and test: `cmake -S . -B build && cmake --build build && ctest --test-dir build`.

## Interfaces provided
```cpp
struct BodyParams { float length; int node_count; float wave_amplitude;
                    float wave_number; float strouhal; int length_passes; };
struct PathPoint { Vector2 pos; float arc; };          // m
struct SharkBody { std::vector<PathPoint> path;        // oldest → nose
                   float phase = 0.0f;                 // rad
                   std::vector<Vector2> spine; };      // [0] nose … [node_count-1] tail tip
SharkBody seedSharkBody(const Kinematics&, const BodyParams&);
SharkBody updateSharkBody(const SharkBody&, const Kinematics&, const BodyParams&, float dt);
```
- `spine` is a `std::vector` sized `node_count` (24), not a fixed array, because `node_count` is a parameter.
- `PathPoint::arc` is **rebased every update** so the oldest kept point has arc 0 and the nose has the largest arc. Only arc differences are meaningful. This keeps float precision bounded on long runs.
- Trimming keeps exactly one point at or beyond L behind the nose, so `nose.arc − path.front().arc ≥ L` and `nose.arc − path[1].arc < L`.
- A nose that has not moved (step = 0) adds no point.
- Seeding writes two path points: `kin.pos − L·heading` (arc 0) and `kin.pos` (arc L).
- `main` uses `SHARK_BODY` with `length = SHARK_LENGTH` (still 0.4 m until issue 02 changes it), `node_count = 24`, `wave_amplitude = 0.1`, `wave_number = 5.3`, `strouhal = 0.3`, `length_passes = 1`. The wave values are not used yet.

For issue 03: place the wave after `placeSpine` in `updateSharkBody`. Tests use a `flatBody()` helper with `wave_amplitude = 0`, so they should keep passing.

## Deviations
- Removed `SHARK_WIDTH` from `fishes.cpp`: the triangle was its only user, and leaving it gave an unused-variable warning. Issue 05 uses the width profile from the spec instead.

## Not verified

- Fish behaviour "unchanged" is by code inspection (no fish code touched), not by a test.
- R16 is by construction (body module has no pixel code); there is no test for it.
- Performance cost of copying the path vector every frame (2 sharks, ~L/(v·dt) points each) was not measured.
