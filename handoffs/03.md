# Handoff 03: Shared motion header and weight split

## Built
- `motion.h` / `motion.cpp`: `MotionParams`, `Commands`, `integrate`, `CLEARANCE_TIE` and the world size, moved verbatim from `fishes.cpp`. The world size moved with the constants it is computed from: `METERS_PER_PIXEL`, `WINDOW_WIDTH`, `WINDOW_HEIGHT`. `fishes.cpp` includes `motion.h` and still uses them for drawing and the window.
- CMake library `motion` (static). Like `shark_body`, it uses raylib's headers only (for `Vector2` and the inline raymath operators) and does not link raylib. Both `fishes` and `shark_body_tests` link it.
- `W_SEPARATION` is gone. Fish separation uses `W_FISH_SEPARATION` = 0.9 and shark separation uses `W_SHARK_SEPARATION` = 0.9.
- `tests/motion_tests.cpp`: checks that the world is 30 × 16 m (spec R21) and checks one `integrate` step by hand. This test also proves that the test executable links `motion` without raylib.

## Interfaces provided
`motion.h`:
- `struct MotionParams`, `struct Commands`: unchanged.
- `Kinematics integrate(const Kinematics &kin, Commands commands, const MotionParams &params, float dt)`: unchanged. dt in s.
- `WORLD_WIDTH`, `WORLD_HEIGHT` in m (y down, as in `kinematics.h`).
- `CLEARANCE_TIE` in m.
- ⚠ Also `METERS_PER_PIXEL`, `WINDOW_WIDTH`, `WINDOW_HEIGHT`. The issue says the world size moves "with the constants it is computed from", and these are those constants.

## Deviations
- `integrate` is now compiled in `motion.cpp` without `-ffast-math -mcpu=native`, the flags `fishes` uses. Before, it was compiled with them. The float rounding of `integrate` may differ in the last bits, so the simulation may not match the old one bit for bit. It does not change behaviour in any way you could see. I did the same as `shark_body`, which is also built without those flags. If you need bit-for-bit equality, give `motion` the same flags. The tests would then also run with fast-math.

## Not verified
- I did not compare the old and new simulations bit for bit.
- I did not check by eye that behaviour is unchanged. I only ran the main executable for 4 s to confirm it starts and runs.
- `integrate` is in a separate translation unit now, and there is no LTO, so it can no longer be inlined into the main loop. I did not measure the cost.
