# Handoff 03: Body wave, phase and length pass

## Built
- `updateSharkBody` now, after placing the nodes on the path:
  1. advances `phase` by ω·dt, ω = 2π·St·u/(2·A·L) with u = `kin.v` (π·u rad/s with the decided values), wrapped to [−π, π];
  2. offsets each node along the local normal by h(s) = A·L·amp(s)·sin(k·s − φ), using the new phase;
  3. runs `length_passes` head-to-tail passes that reset each segment to L/(node_count − 1), keeping its direction.
- amp(s) is a Fritsch–Carlson monotone cubic Hermite through the blog's six points (`WAVE_ENVELOPE`, `interpolateSmooth`, both private to `shark_body.cpp`).
- The local normal at node i comes from the **unwaved** nodes: central difference of i−1 and i+1, one-sided at the ends. The sign is fixed but arbitrary (left of the nose-ward tangent in a y-down frame).
- `seedSharkBody` is unchanged: the first frame is straight and has no wave.
- `tests/body_wave_tests.cpp` covers R8, R9, R10 (straight; turning at r_max at 0.5, 1.0 and 2.5 m/s), R11 and R12 (uneven dt including 0, while turning). It is added to `shark_body_tests` in CMake.

## Interfaces provided
Unchanged from 01. `updateSharkBody` now uses `dt`.
- `SharkBody::phase` stays in [−π, π]. Compare phases modulo 2π.
- `spine` is the drawn centreline: after the wave and the length pass. Node 0 sways around `kin.pos` (±0.06 m at A = 0.1). The tail no longer reaches s = 1 of the path, because the length pass shortens the body along the path.

## Deviations
- **`wave_amplitude == 0` turns the whole wave stage off: no phase advance, no offset, no length pass.** Reason: ω divides by A, so the phase would become NaN. A length pass on an unwaved curved spine moves the nodes off the path by more than R7's 1 mm: I ran it, and three 01/review-01 tests failed with errors up to ~1.3 mm. The issue requires the 01 tests to pass with A = 0, so the spine at A = 0 is exactly the 01 tracer.
- "Interpolated smoothly" was read as monotone cubic Hermite (C1, no overshoot). The blog likely uses a cubic spline. Only the values at the six points are tested. Issue 05's width profile may want the same interpolator. It is currently a private template in `shark_body.cpp`.

## Not verified
- Visual: two stills from a 6 s run show the red polylines undulating, with a larger swing toward the tail. I did not judge from stills whether the beat frequency rises with speed. The user should watch this.
- R11 passed as soon as it was written (peak 0.292 m against 0.30 ± 20 %). The code for R8–R10 already covered it, so there was no failing step.
- R10 at A = 0 is not met in very tight turns (chord vs arc ≈ 0.18 % at R = 0.625 m). This is by design of the deviation above. It is not tested.
- Long-run phase precision is not tested. The wrap keeps it bounded.
