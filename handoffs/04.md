# Handoff 04: Turn bend replaces the nose path

## Built
- The spine is built from the current `kin` alone, by `buildSpine(kin, phase, params)` (private to `shark_body.cpp`):
  1. `bendSpine`: node i is placed on the turn bend's arc at s_i·L behind `kin.pos`. The arc is tangent to `kin.heading` and has curvature κ = r/v (1/m, the sign of r). It is computed in closed form with sin(x)/x and (1 − cos x)/x, so κ → 0 is exact and r = 0 is a straight line.
  2. 03's wave and length pass run on it unchanged. `wave_amplitude == 0` still skips the phase advance, the wave and the length pass.
- v ≤ 0 gives κ = 0, a straight spine. A denormal v makes r/v infinite. All nodes then sit at `kin.pos`, which is the zero-radius limit of the arc. Only tests reach that case.
- `seedSharkBody` is `buildSpine` at phase 0: an ordinary frame with the wave on.
- `updateSharkBody` advances the phase as in 03, then calls `buildSpine`. The previous body is read only for its phase.
- The path record is gone: `PathPoint`, `SharkBody::path`, `pointAtArc`, `placeSpine` and `trimPath`.
- `tests/turn_bend_tests.cpp` covers R7, R6, R19, R20 (straight at v = 0, finite from v = 0 up to v_min) and R12 (uneven dt with v and r changing every step). It is added to `shark_body_tests` in CMake.
- The retired tests listed in the issue are deleted, together with the helpers that only they used.
- `main` is unchanged.

## Interfaces provided
As planned:
```cpp
struct SharkBody {
    float phase = 0.0f;              // rad, [−π, π]
    std::vector<Vector2> spine;      // [0] nose … [node_count−1] tail tip, world m
};
SharkBody seedSharkBody(const Kinematics &kin, const BodyParams &params);
SharkBody updateSharkBody(const SharkBody &body, const Kinematics &kin,
                          const BodyParams &params, float dt);
```
`BodyParams` is unchanged. The bend uses `kin.heading` for the tangent and `kin.r` / `kin.v` for κ. It does not use `kin.phi`.

## Deviations
- In `review_01_round2_tests.cpp`, the helper `flatParams()` now writes 3.0 and 24 inline. The file-level constants `L`, `NODES` and `TOL` were used only by the deleted tests. The kept test's body is unchanged.

## Not verified
- Visual: stills from a 10 s run show two red polylines, each smoothly curved along its whole length. Stills cannot show whether the bend appears all at once when a turn starts. The user should watch this.
- R19 and the new R12 test passed on their first run, because the R7 change already makes the spine depend only on `kin` and the phase. I confirmed that R19 fails against the old path-based module in a scratch build (0.09–0.4 m differences).
- At A = 0, R10 (segment lengths) still does not hold on a curved spine. The chords of the exact arc are slightly shorter than L/23. This is 03's rule, and it is not tested.
- The 14° kink near the tail at v_min and r_max (spec, deferred to 07) was not looked at.
