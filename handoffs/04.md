# Handoff 04: Body outline with caudal taper and grey-bronze fill

## Built
- `buildBodyShape` in `shark_body.cpp`: the body geometry seam. For each spine node i, with s_i = i/(n − 1), it puts an outline point on each side at ±w(s_i)/2 along the local normal. w(s) is `WIDTH_PROFILE` (the spec's shape values table) times `length`, interpolated with the same monotone cubic Hermite (`interpolateSmooth`) as the wave envelope.
- The local normal for the outline (`screenLeft`) uses central differences inside and **second-order one-sided differences at the two ends**. The wave's `spineNormal` is unchanged.
- The caudal fin is the end of the taper. `rigid_parts` is always empty.
- `fishes.cpp`: `drawSpine` is replaced by `drawShark`. It calls `buildBodyShape(body.spine, SHARK_LENGTH)`, converts to pixels, and draws one `DrawTriangleStrip` interleaved right, left, right, left… `SHARK_COLOR` is `{140, 128, 106, 255}` (grey-bronze). Fish drawing is unchanged.
- `tests/body_shape_tests.cpp` (added to `shark_body_tests` in CMake): R13 straight, R13 arcs (R = 3, 1.5 and 0.625 m, both bend directions), R14, R16.

## Interfaces provided
```cpp
struct BodyShape {
    std::vector<Vector2> left;                        // m, one per spine node
    std::vector<Vector2> right;                       // m, one per spine node
    std::vector<std::vector<Vector2>> rigid_parts;    // m, empty until 05
};
BodyShape buildBodyShape(const std::vector<Vector2> &spine, float length);
```
- ⚠ `spine` is `const std::vector<Vector2>&`, not `const std::array<Vector2, N>&`. Reason: handoff 01 made `SharkBody::spine` a `std::vector` sized by `BodyParams::node_count`.
- `left` is on the screen-left of the swimming direction (toward the nose) in the y-down frame. This matches `left` in `drawBody`.
- The draw order right-before-left gives counter-clockwise triangles on screen. The opposite order would be culled by raylib.
- Needs at least 3 spine nodes (the end differences use three).

## Deviations
- The spine parameter type, as above.
- The outline normal differs from the wave normal at the two end nodes. Reason: the first-order end chord tilts the normal by half a segment angle. At the nose (w/2 = 0.075 m) this gave 1.9 mm of error at R = 3 m and 3.7 mm at R = 1.5 m, which breaks R13's 1 mm. I did not change the wave's normal, because that would change issue 03 behaviour.

## Not verified
- R13 is checked exactly only at the width knots. The tests use a 21-node spine so that s_i hits every knot. At the real 24 nodes, only s = 0 and s = 1 land on knots. Between knots the values come from the interpolator, which is not checked independently.
- R14 and R16 tests passed as soon as they were written. The R13 code already covered them, so there was no failing step.
- R17 visual: one still from a 7 s run shows two filled, tapered grey-bronze bodies and blue fish as before. Whether the colour reads as "grey-bronze" and how the shape looks are for the user to judge (issue 06).
- The strip was not checked for self-overlap at the tail in the tightest turns. It is a single colour, so overlap would not show.
