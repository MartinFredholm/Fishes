# Handoff 06: Visual tuning

## Built
- **Shape.** The user compared a straight render with a top-view photo. They approved the width profile, pectoral fins and pelvic fins as they were. The cephalofoil moved 0.01 L forward: leading edge at s = −0.01, wing tips at s = 0.07, midline trailing edge at s = 0.05 (chord 0.06 unchanged). Before, the outline's blunt front (w(0) = 0.05 L) showed ahead of the cephalofoil's swept leading edge.
- **Wall clearance.** `MotionParams` has a new field, `wall_clearance` (m). It moves the walls inward for that entity in `wallRepulsion`, `circleClearance` and `nearWallNormal`. Shark: `SHARK_HALF_SPAN_AT_PECTORAL_TIPS` = 0.2 · `SHARK_LENGTH` = 0.6 m. The clearance is applied around the nose (`kin.pos`), not around the fins. Fish: 0, so fish behave exactly as before. `WALL_BUFFER_DIST` stays 1 m.
- `tests/shape_tuning_tests.cpp`: the outline's front corners (`left[0]`, `right[0]`) lie inside the cephalofoil fan on a straight spine, on arcs with R = 3, 1.5 and 0.625 m bending both ways, and while swimming at 0.5, 1.0 and 2.5 m/s with r = 0 and ±0.8 rad/s.

## Interfaces provided
- `BodyShape` and `buildBodyShape` are unchanged.
- ⚠ The cephalofoil's first vertex is still its attachment point on the spine at s = 0, but it is now **inside** the polygon, not on its boundary. The boundary starts and ends at the leading-edge midline (the first boundary vertex is repeated at the end), so the fan closes around the attachment. The header's contract (a triangle fan around the attachment, wound like the strip) still holds. Code that treats `part[1..]` as an open polyline sees one closing edge more.
- `MotionParams::wall_clearance` (in `fishes.cpp`), as above.

## Deviations
- **The spec was edited**, as the issue requires and with the user's approval, although the implement skill says not to edit the spec. Changes: the shape values heading, intro and cephalofoil row; two new design decisions (shape approved by eye, shark wall clearance); an out-of-scope exception for the clearance; "Deferred decisions: None."
- Two earlier tests encoded the old cephalofoil position. Their expected values changed to the new position, with the same tolerances:
  - `tests/rigid_parts_tests.cpp`: rearmost leading edge back −0.01 L (was 0), tips 0.07 L (was 0.08), midline vertex 0.05 L (was 0.06).
  - `tests/review_05_round2_tests.cpp`: midline vertex at 0.05 L from the attachment (was 0.06).
- The out-of-scope line "no change to the safety filter beyond the R3 constants" is broken by the clearance. Issue 06 allows wall-handling changes the user approves, and the user approved this one ("Add more clearence").

## Not verified
- The wall clearance has no unit test. The wall code lives in `fishes.cpp`, outside the test seams. It was checked with an instrumented copy of `fishes.cpp` (scratchpad, not in the repo). Before: in a 90 s and a 120 s run, a part crossed a wall in 13–15 % of frames, by up to 0.43 m (pectoral tips), 0.25 m (cephalofoil) and 0.14 m (outline). After: in a 180 s run, no part crossed in 10,551 frames, and the closest was 0.06 m (a fin tip). Random spawns, so other runs may get closer.
- No one has watched the effect on hunting: the shark now turns away from walls earlier, so fish near the walls are harder to reach.
- Cover in turns is tested only at the attachment's corners, with a 0.0037 L (1.1 cm) margin in a straight spine.

## Fix passes
- Round 1: removed the comment on `SHARK_MOTION.wall_clearance`. Its meaning is now in the name `SHARK_HALF_SPAN_AT_PECTORAL_TIPS`. No behaviour change.
