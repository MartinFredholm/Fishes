### Non-blocking notes
- `integrate` lost `-ffast-math -mcpu=native`. Before this change it was compiled inside `fishes.cpp` with those flags. Now it is compiled in the `motion` library with `-Wall -Wextra` only. The generated code differs (FMA contraction, operation order). Its results differ in the last bits: 36 000 steps from the same start with the same commands end at pos.y −0x1.5e9caep+5 against −0x1.5e9c3ap+5. Not blocking, because the main program cannot show the difference: it seeds raylib's RNG from the clock and uses the wall-clock frame time, so no two runs repeat anyway. It matters if someone compares runs bit for bit, for example a probe that builds `integrate` with different flags than the main program. Options: give `motion` the same flags as `fishes`, or accept it. The user decides.
- `motion.h` now holds `WINDOW_WIDTH`, `WINDOW_HEIGHT` and `METERS_PER_PIXEL`, which are drawing settings, in a dynamics header. The issue asks for this ("the constants it is computed from"), so it is correct here. It is a candidate for the planned refactor.
- `tests/motion_tests.cpp`: the `integrate` test's expected values follow from the forward Euler formulas by hand (1 + 1·0.1, 0.5·0.1, 1 + (2−1)/1·0.1, 0.5 + (1−0.5)/0.5·0.1), so they do not only restate the code. The world-size test pins 30 × 16 m, which the spec relies on (R21).
